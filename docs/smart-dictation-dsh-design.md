# Smart Dictation для DSH: дизайн v1.0

Статус: реализовано и принято владельцем для DSH Web. Документ описывает фактическую архитектуру
`1.0.1`, а не ранний черновик.

## 1. Продукт

Диктовка в композер DSH: русская речь, английские технические термины, пунктуация и личный словарь.
Инференс локальный, без облачных speech API. Текст всегда вставляется в черновик и никогда не
отправляется автоматически.

## 2. Пользовательский интерфейс

- Одна круглая кнопка 28×28 в слоте `conversation.input.activity`.
- Одна и та же кнопка для старта, остановки, отмены, повтора и вставки; размер и позиция не меняются.
- Состояние передают глиф, кольцо уровня и точка статуса. Отдельных подписей «Стоп»/«Запись» нет.
- `Escape` отменяет запись; 120 секунд — жёсткий предел.
- Карточка обучения появляется над композером, не перекрывает его, закрывается `Escape`/«Нет» и
  переводит фокус на «Да».
- Настройки — отдельная секция `settings.section` с id `smart-dictation`, а не кнопки в композере.

## 3. Поток данных

```
микрофон → MediaRecorder → 16 kHz mono PCM16 WAV → /api/.../speech/transcribe
         → Host GigaAM v3 ONNX → core: пунктуация + глоссарий
         → редактируемый черновик → (после отправки) карточка обучения
```

Аудио не сохраняется на диск. Хост сериализует инференс, чтобы одна ORT-сессия не выполняла два
распознавания одновременно.

## 4. Словарь

- Источник истины — файл в каталоге данных DSH; `localStorage` только кэш.
- Стартовый словарь создаётся только при отсутствии файла. Явно пустой словарь остаётся пустым.
- Запись идёт через `glossary/read` и `glossary/replace` с `expectedRevision`.
- Конфликт ревизий не перезаписывает чужие правки: клиент перечитывает документ и применяет дельту
  (удаление/обучение) повторно; импорт при конфликте завершается ошибкой.
- Повреждённый JSON карантинится; `repair()` восстанавливает `.bak`, в том числе если файл уже был
  перемещён предыдущим чтением.
- Обучение предлагает только термины, реально исправленные в отправленном сообщении; вариант
  добавляется к существующему каноническому термину, а не отбрасывается.

## 5. Модель

- GigaAM v3 E2E CTC INT8, ~225 МБ, ONNX Runtime.
- Скачивание с Hugging Face или зеркала, SHA-256, атомарный rename, `.part`, отмена.
- Повреждённый готовый файл переименовывается и скачивается заново.
- Неудачное создание ORT-сессии не кэшируется навсегда.
- Препроцессор `assets/gigaam_v3.onnx` входит в пакет провайдера.

## 6. Отказы и приватность

- Нет доступа к микрофону — понятная ошибка, запись не начинается.
- Отмена во время запроса разрешения останавливает поток, если браузер выдал его после отмены.
- Любой сбой финализации освобождает треки и `AudioContext`.
- Ошибка распознавания не портит черновик; pending-текст можно вставить повторно.
- Транскрипты не логируются; аудио не персистится.

## 7. Пакеты и установка

`core` (private) → `provider` → `client` → `bundle`. Установочный артефакт — bundle `.tgz` из
GitHub Release; его зависимости указывают на те же release-ассеты. Пакеты `provider`/`client` можно
публиковать в npm отдельно, но установка bundle от npm не зависит.

## 8. Вне области v1.0

Windows-оболочка, системная вставка в любое окно, потоковые субтитры, синтез, облачные провайдеры.
